# Electron / Electrobun + CEF - recorded baseline

Measured on 2026-11-04 (Asia/Bangkok), Apple M4 Pro, macOS arm64, 24 GiB RAM. Both prototypes use the browser at commit `011d155` (top, left and right tabs). The live Electron application has since added more features; these results compare the pinned prototypes.

**Decision: continue browser development in Electron.** Keep the Electrobun + CEF port as an experiment. Electron started faster, used less observed memory and idle CPU, and passed more browser feature checks on this machine. CEF had a faster tab-switch proxy. These observations do not establish a framework-wide ranking.

[Machine-readable samples, environments and checks](2026-11-04.json). Electron: Chrome/156.0.8078.75; Electrobun + CEF: Chrome/156.0.8078.17. Electrobun 2.0.5 bundles Bun 1.4.4.

## BrowserBench

Median of three full passes per suite/app. **Higher is better** for all three scores. The default workloads were unchanged. All 18 accepted passes were focused and visible at start and kept a 1280 x 750 viewport at 2x scale. Both apps detected a 120 fps target for MotionMark.

| Official suite                                                    | Electron | Electrobun + CEF | CEF relative to Electron |
| ----------------------------------------------------------------- | -------: | ---------------: | -----------------------: |
| [Speedometer 3.1](https://www.browserbench.org/Speedometer3.1/)   |    54.94 |            49.45 |                   -9.98% |
| [JetStream 3.0](https://www.browserbench.org/JetStream3.0/)       |   387.65 |           387.57 |                   -0.02% |
| [MotionMark 1.3.2](https://www.browserbench.org/MotionMark1.3.2/) |  5203.01 |          4134.55 |                  -20.54% |

JetStream is effectively tied. Each pass uses a new process and a temporary Electron profile or unique CEF tab partition. The planned order alternates apps; resumed retries run later. Five invalid, interrupted or setup-failed MotionMark attempts are recorded separately and excluded from score summaries. No renderer polling runs during the measured workload.

The 22 common automated browser checks pass in Electron; 21 pass in CEF. CEF does not provide the load-error event needed for the copied retry screen. The tested CEF runtime disables the Chromium OS sandbox; its separate RPC sandbox still blocks native application commands from remote pages. The CEF port is not ready for use as a secure general-purpose browser. Native menus, downloads, DRM, extensions and session restore need additional verification.

## Method and limits

The full per-run data, artifact hashes, feature outcomes and exclusion reasons are in the JSON archive. Large generated raw workload data, logs and screenshots are not committed. Fresh runs produce these artifacts under `benchmarks/results/`.

Both apps use optimized Svelte assets inside unsigned development runtimes. OS caches are warm; CEF keeps its shared root/UI cache. RSS sums may double-count shared memory, and tab switching includes automation/observation overhead. The CEF first-view retry remains included in its measured navigation latency. Other desktop apps stayed running; this was not a thermally controlled lab run.

## Repeat

With Node, pnpm and Bun installed on macOS arm64, run from the repository root:

```sh
pnpm install --frozen-lockfile
node benchmarks/prepare.mjs
node benchmarks/run.mjs
node benchmarks/browserbench.mjs
```

The local runner exits nonzero for the documented CEF network-error feature failure and still writes its report. BrowserBench requires AC power and tens of minutes without interaction with the benchmark windows. See [the benchmark guide](../README.md) for limits, flags and resume behavior.
